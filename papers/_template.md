# 论文标题（中文译名）

> **一句话结论**：这篇论文用一句话说清了什么。读者看完这一句就知道值不值得往下读。

| 项目 | 内容 |
| --- | --- |
| 出处 | 会议/期刊名 + 年份（附 arXiv 或 DOI 链接） |
| 作者单位 | 第一作者单位，判断可信度和复现条件 |
| 任务类型 | 抓取 / 装配 / 移动操作 / 规划 / 策略学习 |
| 实验平台 | 具体硬件型号，这决定了我们能否复现 |

## 要解决什么问题

用两三句说清痛点，要具体到场景。不要写"现有方法存在局限性"这种空话，写清楚"在什么样的情况下，现有方法会怎样失败"。

## 方法

分点写，每点一句主谓宾。控制在 3～5 点。

1. 第一步做了什么。
2. 第二步。
3. 第三步。

关键设计选择单独说明为什么这么做，而不是"作者提出了一个模块"。

## 对我们的意义

- **能复现吗**：需要什么硬件、什么开源代码、大致工作量。
- **对应哪条产品线**：明确写出型号，不要泛泛说"我们的机械臂"。
- **客户会怎么问**：列出 2～3 个高校老师最可能追问的点，以及怎么答。
